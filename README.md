## What is Entiendo?

Entiendo is a codebase intelligence tool that lets you understand, visualize, and modify any GitHub repository using plain English. Clone a repo, ask a question, and get back:

- A **live Mermaid diagram** of the architecture or data flow
- A **streamed explanation** of how specific code works, enriched with semantic search results
- A **diff proposal** with exact SEARCH/REPLACE edits — review and accept with one click
- A **test suite** scaffolded from the actual file content and dependency graph
- **Clickable file bubbles** — every file in the repo floats as an animated node; click any to inspect it with syntax highlighting

All of this happens through a single natural-language query. No commands, no file paths — just describe what you want.

## Key Features

### Diagram Generation
Ask for any type of diagram and Entiendo picks the right Mermaid type automatically:
- **Dependency / import graphs** — built from real AST import edges, not LLM guesses
- **Class diagrams** — extracted from actual `class`/`extends`/`implements` declarations
- **Flowcharts, sequence diagrams, ER diagrams** — generated by LLM enriched with graph context
- Export any diagram as an SVG file or copy the Mermaid source directly

### Knowledge Graph
Every indexed repo gets an in-memory code graph built from static analysis:
- Tracks imports, exports, function calls, class hierarchies, and interface implementations
- Used to give the LLM accurate structural context (which files import what, impact radius of a change)
- Powers `toMermaid()` and `toClassDiagram()` directly — zero hallucination for structural diagrams
- `waitForGraph()` promise gate ensures nodes never run before indexing is complete

### Live Token Streaming
LLM responses stream token-by-token via Socket.io. The output panel opens immediately and content appears in real time — no waiting for the full response.

### RAG with Automatic Fallback
Semantic search is available without any external services:
- **With Qdrant**: embeddings stored in a persistent vector database (`http://localhost:6333`)
- **Without Qdrant**: automatic fallback to in-memory cosine-similarity search — no config needed
- `waitForIndex()` promise gate prevents race conditions between indexing and retrieval

### Multi-Turn Conversation Memory
The agent maintains conversation history across queries within a session. Previous queries and their outputs are injected into prompts so follow-up questions have full context.

### Git Diff Awareness
On each query, Entiendo captures `git log` and `git diff HEAD~1 HEAD --stat` from the cloned repo and injects it into relevant prompts — the LLM knows what recently changed.

### Deterministic Refactoring
Code edits use structured SEARCH/REPLACE blocks:
- Exact string matching — no guessing, no whole-file rewrites
- Multi-file support: up to 5 files in a single refactor pass
- Diff viewer with per-file tabs and accept/reject controls
- Applied changes written back to disk immediately on accept

### Test Generation
The `test` intent auto-detects the test framework from `package.json` (Vitest, Jest, Mocha, pytest) and generates:
- Unit tests for every exported function and class
- Edge cases and error conditions
- Mocked dependencies derived from the knowledge graph

### Interactive Bubble Canvas
Every file in the cloned repo is visualized as an animated floating bubble:
- Size scales with file size (log scale)
- Color-coded by type: indigo = source code, emerald = docs, amber = config
- Animated via Framer Motion keyframes — no `requestAnimationFrame` loops, no React re-renders during animation
- Nearest-neighbor SVG connection lines computed once via `useMemo`
- Click any file bubble to open it in the syntax-highlighted file viewer

### Syntax-Highlighted File Viewer
Click any bubble to inspect the raw file content:
- Line-numbered table layout with sticky gutters
- Regex-based highlighting for TypeScript/JavaScript and Python
- Tokens: keywords (violet), strings (green), comments (slate/italic), numbers (amber), types (cyan)
- Copy-to-clipboard button

### Agent Telemetry
A live log panel shows every step the agent takes:
- Timestamps captured at log creation (not render time)
- Color-coded: indigo = user query, violet = node transition, emerald = success, red = error
- Auto-scrolls to latest entry
- Pulsing `TRAVERSING_GRAPH_SPACE...` indicator while processing

### Conversation History Chips
Previously asked queries appear as colored chips above the input bar:
- Last 4 queries shown, newest first
- Color matches the intent node that handled them (violet = diagram, sky = explanation, emerald = tests, amber = refactor)
- Click any chip to restore the query

## Architecture

```
Browser (React + Socket.io-client)
    │
    │  WebSocket (Socket.io)
    ▼
Express + Socket.io Server (server.ts)
    │
    ├── Clone repo (degit, async)
    ├── RAG Indexer  ──────────────► Qdrant (optional) / In-memory cosine
    ├── Graph Indexer ─────────────► In-memory AST code graph
    │
    └── LangGraph Orchestration
            │
            ├── entryNode  (router — classifies intent)
            │
            ├── macro_structure  ──► LLM stream ──► tokenEmitter ──► socket
            ├── micro_logic      ──► LLM + file content ──► Mermaid
            ├── diagram          ──► graph.toMermaid() | toClassDiagram() | LLM
            ├── deep_explanation ──► RAG + graph context ──► LLM stream
            ├── refactor         ──► LLM SEARCH/REPLACE ──► diff engine ──► store
            ├── test             ──► LLM + graph deps ──► LLM stream
            └── error_handler
```

### Intent Routing

| Intent | Trigger | Output |
|---|---|---|
| `macro_structure` | "overview", "architecture", "project structure" | Markdown (streamed) |
| `micro_logic` | "how does X file work", "sequence diagram" | Mermaid |
| `diagram` | "draw", "graph", "diagram", "class diagram" | Mermaid (graph-first) |
| `deep_explanation` | "how does X work", "explain", "walk me through" | Markdown (streamed) |
| `refactor` | "fix", "refactor", "optimize", "add feature" | SEARCH/REPLACE diff |
| `test` | "test", "generate tests", "unit tests" | Markdown (streamed) |

### Core Modules

| Module | Purpose |

## Setup

### Requirements
- Node.js 18+
- A Gemini API key ([get one free](https://aistudio.google.com))
- Qdrant (optional — falls back to in-memory search automatically)

### Installation
```bash
git clone https://github.com/akashcheema05796-del/Entiendo.git
cd Entiendo
npm install
```

### Environment Configuration
Copy `.env.example` to `.env`:

```bash
cp .env.example .env
```

| Variable | Required | Description |
|---|---|---|
| `GEMINI_API_KEY` | Yes | Server-side LLM and embeddings (Gemini 1.5 Flash/Pro, text-embedding-004) |
| `VITE_GEMINI_API_KEY` | Yes | Client-side repo analysis on clone (Gemini 1.5 Flash) |
| `QDRANT_URL` | No | Qdrant vector store URL. Default: `http://localhost:6333`. Falls back to in-memory if unavailable. |
| `NODE_ENV` | No | Set to `production` to serve the Vite build from `/dist` |

### Run (Development)
```bash
npm run dev
```
Opens on `http://localhost:3000`

### Run (Production)
```bash
npm run build
NODE_ENV=production npm start
```

### Optional: Qdrant (persistent vector search)
```bash
docker run -p 6333:6333 qdrant/qdrant
```
Without Qdrant, RAG falls back to in-memory cosine similarity — no config needed.

## Usage

1. **Enter a GitHub repo** in the header input (format: `owner/repo`)
2. **Wait for clone** — the bubble canvas fills with animated file nodes
3. **Ask anything** in the input bar:
   - *"Show the project architecture"*
   - *"Draw a dependency graph"*
   - *"Explain how the auth flow works"*
   - *"Refactor the API handler to use async/await"*
   - *"Generate tests for utils.ts"*
   - *"Show a class diagram of the system"*
4. **Results appear** in the right panel — diagrams render as SVG, explanations stream live
5. **Click any file bubble** to inspect it with syntax highlighting
6. **Accept or reject** refactor proposals in the diff viewer

## Privacy

Local-first data policy. Code content is processed in secured Gemini reasoning clusters. Identifiers and session metadata are cached in a private SQLite instance (`.session_cache.db`), excluded from version control. No code is stored beyond the active session.
